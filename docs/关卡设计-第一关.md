## 一、调研结论：《武士刀零》的关卡设计原则

### 1.1 房间级结构：一屏 = 一次完整遭遇

《武士刀零》的关卡不是"一段路 + 沿途撒敌人"，而是**一屏 = 一次战斗谜题**：

**一个遭遇单元 = 进入屏幕 → 3~6 秒内解决 2~4 个敌人 → 走出屏幕（或最后一个敌人死亡）= 检查点**

三条硬规则：

1. **一屏是一次性可解完的**。玩家进屏就能看到全部威胁（敌人不藏在屏幕外）。屏幕边界本身就是节奏的呼吸，也是隐式检查点。
2. **每屏只教/考一个新变量**。第一屏考"能不能砍到人"，后面的屏才考"子弹时间穿弹幕"。同一屏不会既考跳跃又考多敌应对。
3. **敌人是谜题元件，不是血量单位**。因为一击必杀，敌人数量 ≈ 解法复杂度：1 敌 = "怎么靠近"；2 敌 = "先处理哪个、从哪一侧进"；3 敌 + 地形 = "路线规划"。这就是为什么它从不一屏塞 8 个敌人——那会让解法退化成乱按。

由于它**不做程序生成**（制作人 Justin Stander 在 GDC 2016 采访中明确否认 roguelike 与程序生成，强调"每一个关卡都是手工打造的"），每个房间的敌人站位都是**算过时间和距离的**：巡逻兵的转身点卡在你冲刺距离的临界值上，枪兵的前摇刚好够你按 Shift。这是"手感"的真正来源。

### 1.2 难度曲线：教的是"什么时候用"，不是"怎么按"

它的教学几乎不弹教程框，**用环境当教具**。固定三步：

> **安全演示 → 环境逼你用 → 死亡惩罚你不用**

可核实的第一关（废弃工厂）教学序列：

- **跳跃**：开头一个要按 W 跳上去的高台；跳不上去时提示"在空中攻击一下试试"（顺手教了空中斩）。
- **下劈破地形**：把准星对准地面攻击，打穿地板掉到地下室。教的不是"攻击键"，而是"刀能作用于场景"。
- **墙跳**：几个反跳上去，且**跳一次要松开再跳第二次**——直接教了输入手感的边界。
- **子弹时间**：按提示用时间减速**穿过旋转的风扇**。关键点：教这个技能时，**附近没有敌人**。玩家在零死亡成本的情况下把"按住 Shift 世界会变慢"刻进肌肉记忆，等后面枪兵出现，Shift 才有战斗含义。

难度阶梯的形状是"**加信息维度**"，不是"加血量和数量"：

| 阶段 | 新增变量 | 玩家学到的判断 |
|---|---|---|
| 第一关（废弃工厂） | 跳跃、斩击、破地形、墙跳、**子弹时间（无敌人）** | "我有这些能力" |
| 早期战斗屏 | 静止敌 → 巡逻敌 → 2 敌不同高度 | "先处理谁、从哪一侧进" |
| 引入枪兵 | 子弹（大前摇、慢速） | "子弹时间是用来处理和时间有关的威胁的" |
| 酒店 | 可投掷物（花盆→酒瓶→台灯，且不能跨屏携带）、可招架的敌人、破门 | "我有不止一把刀" |
| 舞厅 / 监狱 | 摄像头视野、机枪炮台、烟雾、拉闸机关、激光 | "环境也是武器和敌人" |

### 1.3 「一击必杀 + 快速重开」对关卡设计的特殊要求

这个组合把游戏从"资源管理"变成了**"知识 + 执行"**。死亡不是扣血，而是"这道题我还没解出来"。

**(a) 检查点按"机制"放，不按"距离"放。**

**唯一正确的原则：检查点放在"新机制首次出现的那一屏"的入口。**

- ❌ "走廊太长，中间补一个检查点" —— 玩家复活后要走 5 秒空路，这 5 秒会摧毁重开的手感。
- ✅ "下一屏要教子弹时间，就把检查点放在那屏的入口"，让玩家 0.5 秒内进入重试。

**判据：如果一段内容玩家可以做到"从来不死"，它就不需要检查点。检查点只服务于"会死的地方"。**

同时要守住 0.45 秒的纯度：**不加读条、不加闪屏、不加 "YOU DIED" 淡入、不加死亡音效尾巴**。重开时间预算是 **≤2 秒从死亡到重新可控**（含 0.45 秒）。

**(b) 让玩家觉得"这是我解出来的"的 4 个条件：**

1. **死亡必须可归因，而且归因到"我的执行"，不是"我没看见"**。屏幕外来的攻击 = 不可归因 = 玩家骂游戏；屏幕内的威胁 + 0.35 秒前摇 + 独立音效 = 可归因 = 玩家骂自己。**本关的第一次死亡，绝不能死于信息不足。**
2. **每个房间至少两条解**：保守路线（利用高度差、等时机、逐个处理）和炫技路线（子弹时间贯穿、一次冲进去连砍两个）。有两条路玩家才会觉得"我用了我自己的方式"；只有一条路，那叫背答案。
3. **确定性**。不许随机巡逻点、随机开火时机、随机弹道。一击必杀 + 随机 = 赌博，玩家的进步曲线就不存在了。
4. **"局部最优"和"帅"要能区分开**。一屏同时存在"最省事的通过方式"和"最快的通过方式"，玩家才会自发去追后者——这就是它耐重开的原因。子弹时间天然提供了这个空间（全场只有你能动）。

**(c) 三条负面约束（违反任何一条，这个组合就会崩）：**

1. **不许用无敌帧 / 血量 / 护盾来"救"难度**。一旦给容错，一击必杀的紧张感就没了，你会被迫不断加敌人数量，最后做成一坨。难度的正确旋钮是**布局和信息**，不是数值。
2. **不许让死亡变成"我不知道该干什么"**。每次死亡后，玩家心里必须立刻浮现一个**具体动作**（"我该先跳上平台"），而不是"这关好难"。
3. **不许把战斗和精密平台跳跃放在同一屏**。掉坑死和被打死混在一屏时，学习反馈互相污染，玩家什么都学不到。

## 二、第一关：6 屏布局设计

### 2.1 设计目标与总参数

**唯一目标：让玩家在第 6 屏结束时，能凭直觉用出「冲刺砍」和「子弹时间」，并且确信"死了立刻重来是安全的"。**

| 项目 | 值 | 依据 |
|---|---|---|
| 窗口 / 关卡可视高度 | 960 × 540 | `main.tscn` Background `offset_right/bottom` |
| **地面表面 y** | **480** | `Ground` 位置 y=500，`ShapeGround` 高 40 → 顶面 500-20=480 |
| 玩家碰撞体 | 18 × 30（脚底 = y+15） | `ShapePlayer` |
| 敌人碰撞体 | 26 × 34（脚底 = y+17） | `ShapeEnemyBody` |
| 站立在地面上的中心 y | **玩家 465 / 敌人 463** | 480 − 15 / 480 − 17 |
| 攻击框 | 52 × 34，中心在身前 33 px | `ShapeAttack` + `AttackArea.position.x = 33` |
| 一屏（遭遇单元）宽度 | **960 px** | 等于窗口宽，一屏一遭遇，符合《武士刀零》切分法 |
| 关卡总宽 | **5760 px**（6 屏） | |
| 相机动线 | 跟随玩家，相机 limit 钳制在 0~5760 | 保留滚动相机，用检查点区域模拟"遭遇边界" |
| 每屏预期重开次数 | 0 / 1~2 / 2~3 / 2~3 / 2~4 / 5+ | 见 2.8 |
| 预期总时长 | **75~100 秒**（速通 ≤45 秒） | |

**数值换算依据**（用你的实际常量算的，摆关卡时要靠这些）：

| 动作 | 计算 | 结果 |
|---|---|---|
| 普通跳跃最高点 | `v²/2g = 430²/3000` | **≈ 62 px** |
| 全高跳跃滞空 | `2v/g = 2×430/1500` | ≈ 0.573 s |
| 全高跳跃水平位移 | 0.573 × 220 | **≈ 126 px** |
| 冲刺位移 | 620 × 0.14 | **≈ 87 px** |
| 冲刺期间高度变化 | 无视重力 | **0 px（完全水平）** |
| 攻击范围 | 身前 33 ± 26 | 距玩家中心 **7 ~ 59 px** |
| 子弹时间相对倍率 | 1 / 0.30 | 玩家相对世界快 **3.33 倍** |
| 子弹时间最长持续 | 1.6 / 1.0 | **1.6 s**（恢复 0.55/s，回满需 ~2.9 s） |

> ⚠️ **重要推论**：跳跃只有 62 px 高，所以**所有平台的高度差必须 ≤ 55 px**，否则玩家跳不上去（可用冲刺弥补，但冲刺是水平的，不能增加高度）。本文档所有平台都遵守这条。

| 地面（保留） | 中心 (480, 500) | 960 × 40 | 表面 y=480，保留 |
| 平台 A（保留） | (320, 425) | 180 × 22 | **注意**：原场景是 y=380（离地 100 px，跳不上去）。改为 425（离地 **55 px**）才跳得上去 |
| 平台 B（保留） | (640, 410) | 140 × 22 | 原场景 y=300。改为 410（离平台 A 顶面 15 px 高度差，轻松） |
| P 出生点 / **C1** | (80, 465) | — | 检查点 1 |
| E1 静止靶子 | (760, 463) | 26 × 34 | 背对玩家（朝右），**站着不动** |

**敌人的两个可接近方案（这就是"两条解"）：**

1. **地面直冲**（保守）：从 x=80 跑到 x=700，进入攻击范围 → 砍。**必成功，零难度**。
2. **上平台绕后**（炫技）：跳上平台 A（离地 55 px）→ 跳上平台 B（+15 px）→ 从 B 右缘（x=710）跳下 → 空中砍。视觉上更帅，但**风险和收益相同**。

**玩家心理曲线：**

- 「哦，我跳上去了。哦，我一刀就把它砍死了。**这游戏主角很强。**」
- 这一屏的功能就是"让玩家成功一次"，建立"刀很快、我很强"的自我认知。
- **不允许任何死亡**。这里的两个平台不是挑战，是**承诺**：告诉玩家"这游戏有立体动线"。

**预期重开次数：0。预期完成时间：8 秒。**

> 🔧 **摆放要点**：
> - E1 站在 x=760，**不要**放在平台 B 正下方（x=640），否则玩家会误以为"必须跳下去才能打到"，把一个零难度教学屏变成一次跳跃测试。
> - 平台 A 必须能"跳一次就上"（高差 ≤55 px）。如果你保留 y=380，玩家会跳 3 次失败然后怀疑自己的操作，这是最坏的第一印象。

### 2.4 屏 2 ——「巡逻兵：冲刺要收得住」（x 960–1920）

**第一次出现死亡风险。教"冲刺的停止位置"和"选择时机"。**

| 元素 | 坐标 | 参数 | 说明 |
|---|---|---|---|
| **C2 检查点区域** | x 960–1060，y 420–540 | — | 复活点 **(980, 465)** |
| W 巡逻敌人 | 出生点 (1350, 463) | `patrol_left = -170`、`patrol_right = +170` → 巡逻区间 **x 1180 ~ 1520**；`patrol_speed = 70`；`turn_pause = 0.25`；**`can_chase = false`** | 用 `PatrolEnemy.gd` |
| 障碍地形 | (1650, 455) 一个 100 × 60 的小台 | — | 屏右端的视觉终点，挡住"直接冲过去" |

**为什么 `can_chase = false`**：第一关不要追击。追击会把"玩家主动选择时机"变成"玩家被追着跑"，而屏 2 的教学目标是**主动**——等它转身再上。

**两条解：**

1. **保守（稳）**：站在 x≈1130 不动，观察巡逻兵来回走。等它转身向右走远（x>1400），再走过去砍背。**零风险，需要耐心。**
2. **炫技（快）**：在它转身朝你走来的瞬间冲进去，`DASH`（87 px）贴脸砍。**如果时机错，冲刺的 87 px 位移会让你直接撞进它的 Danger 区 → 死。**

**玩家心理曲线（第一次死亡在这里）：**

1. 第一次尝试：看到敌人 → 直接朝它冲过去 → 撞上 → 死。
2. 「啊？我怎么死的？……哦，**它一直在走，我冲过去刚好迎面撞上**。」
3. 第二次：等它转身 → 从背后砍 → 过。
4. 第三次（如果有人告诉他可以更快）：「原来它刚转身的时候，我冲刺进去也来得及。」

**死因归纳**：**冲刺的距离比你以为的长**。这是本屏唯一要教的东西。玩家必须在这里学会"冲刺前先看敌人朝向"。

**预期重开次数：1~2。预期完成时间：12 秒。**

> 🔧 **摆放要点**：
> - 巡逻区间宽 340 px，跑一个来回约 **4.9 秒**（340×2÷70 + 2×0.25 停顿）。这个周期要"够眼看、不够犹豫"——太短玩家看不清规律，太长会烦。
> - 巡逻兵**朝向必须可视**（`PatrolEnemy.gd` 已经做了 `_sync_visual()` 翻转色块，另外 `_draw()` 里画了朝向标记，调试时能看到）。
> - **这一屏不能有沟**。沟 + 敌人 = 死因归因污染。

### 2.5 屏 3 ——「子弹时间入门」（x 1920–2880）

**这是全关最重要的教学屏，是你唯一能让"子弹时间"变成有用能力的场合。**

⭐ **设计核心：让"危险与时间有关"，子弹时间才有意义。**

在现有能力下，这个"与时间有关的危险"就是 **P0 里那个定时/匀速移动的 Hazard**（下面称"危险物"或"子弹"）。

| 元素 | 坐标 | 参数 | 说明 |
|---|---|---|---|
| **C3 检查点区域** | x 1920–2020 | — | 复活点 **(1940, 465)** |
| 平台 F | (2140, 425) | 160 × 22 | 离地 55 px |
| 平台 G | (2560, 410) | 140 × 22 | 比平台 F 高 15 px |
| **S1 危险物发射器** | (2680, 420) | 每 **2.2 s** 向左发射一个子弹；子弹 `velocity = (-140, 0)` | 子弹慢到"肉眼能看清" |
| 子弹参数 | 生成于 (2680, 420) | 速度 140 px/s，向左飞，飞出屏幕（x<1920）自动销毁 | 从 2680 到 1920 需要 **5.4 秒**，中间玩家有充足判断时间 |
| E2 | **(取消)** | — | 屏边界上的敌人容易造成"半屏外威胁"，删掉 |

**教学三步（严格按顺序，不要打乱）**：

1. **第一发子弹是"够不到的"**：玩家刚进屏（x≈1960），子弹从 x=2680 出发，玩家还没走到它路径上就已经自然飞过/消失。玩家看到了子弹的**速度和大小**，但没有风险。→「原来子弹这么慢。」
2. **第二发是"必须处理的"**：玩家走到 x≈2100~2200 时，下一发子弹到达。**此时玩家必须按住 Shift**——按住之后世界降到 30%，子弹从"有点快"变成"慢慢飘过来"，玩家从容地从它上面跳过去（或用 3.33 倍相对速度从它下面冲过去）。
3. **不按 Shift 也能过，但会很难**——这就是关键。如果玩家硬冲：子弹速度 140 px/s、玩家 220 px/s，理论上能跑赢，但**需要精确的间距判断**，绝大多数新手会死。

**玩家心理曲线：**

1. 「一颗子弹飞过来了……我跳过去！」→ **死**（跳的 62 px 高度不够/时机偏了）。
2. 「我再试一次……还是死。」
3. 「等等，**说明里说过 Shift**。……哇，**整个世界都慢下来了，只有我在正常跑**。」
4. 「原来这游戏的核心是**我控制时间**。」← **这是全关的情感高点，必须发生在这里。**

**预期重开次数：2~3。预期完成时间：15 秒。**

> 🔧 **摆放要点**：
> - 危险物**必须有前摇**：发射前 0.3 秒，发射器色块闪白（`modulate` tween）。这是"可归因"的必要条件，缺了玩家会觉得被坑。
> - 子弹**必须大而亮**（对比地面色 `Color(0.24,0.35,0.5)`，用亮黄/亮红）。像素风里"看得见"比"物理正确"重要 10 倍。
> - **发条周期 2.2 秒**：短于 2 秒玩家来不及观察，长于 3 秒会无聊。这个值可以直接在检查器里调。
> - **子弹时间能量 1.6 秒**：从 2680 飞到 1920 需要 5.4 秒，**玩家不可能全程开慢动作**。这是设计意图——子弹时间必须是"看准了再按"的爆发工具，不是常驻状态。恢复 0.55/s，用掉 1.6 秒后要等 2.9 秒才能回满，所以**每个危险窗口最多开一次**。

### 2.6 屏 4 ——「双层弹幕」（x 2880–3840）

**把屏 3 的单一时间威胁升级为"相位差"，教玩家读"安全窗口"。**

| 元素 | 坐标 | 参数 | 说明 |
|---|---|---|---|
| **C4 检查点区域** | x 2880–2980 | — | 复活点 **(2900, 465)** |
| E3 静止靶子 | (3300, 463) | 站着不动 | 诱饵：让玩家想"先砍了它再躲" |
| E5 静止靶子 | (3700, 463) | 站着不动 | 屏右侧的堡垒，必须在弹幕下处理 |
| **S_hi 发射器** | (3460, 300) | 周期 **2.6 s**，子弹速 `(-180, 0)`，生成 y=300 | 高位子弹，**必须蹲/贴地冲过，或跳到平台上躲** |
| **S_lo 发射器** | (3560, 463) | 周期 **1.7 s**，子弹速 `(-180, 0)`，生成 y=463 | 低位子弹，**在地面高度飞，必须跳过去** |
| 平台 H | (3060, 425) | 140 × 22 | 可选躲避点（离地 55 px） |
| 平台 I | (3380, 425) | 140 × 22 | 高位子弹的"安全岛"：站在这里子弹从脚边过 |

**核心机制：两个发射器周期不同（1.7 s vs 2.6 s），所以它们的子弹会呈现"有时重叠、有时错开"的相位差。** 玩家必须学会**等一个"两颗子弹之间有足够空档"的窗口**再前进。

**两条解：**

1. **保守（稳）**：站在平台 H 上观察 3~4 个周期，等一个明显的大空档，冲过去砍 E3，退回平台 I，再等窗口砍 E5。
2. **炫技（帅）**：一开屏就按住 Shift，趁世界慢下来时连续处理 E3 和 E5，用 3.33 倍相对速度在两个发射器之间来回。全程约 12 秒内解决。

**心理曲线：**

1. 进屏 → 「两个发射器！我先砍这个（E3）」→ 砍死 E3 → 转身撞上低位子弹 → **死**。
2. 「它们**是不同的节奏**……我好像不能一直往前走。」
3. 学会等窗口 → 过。→「**我读懂了它们的规律。**」

**预期重开次数：2~3。预期完成时间：18 秒。**

> 🔧 **摆放要点**：
> - **两个发射器的周期必须是"互质感"的**（1.7 和 2.6，比值 0.65，不是 1:1、1:2 这种整齐关系）。整齐的公倍数关系会让玩家找到"永久安全节拍"，难度崩塌；互质关系保证安全窗口**周期性变化**，玩家必须每次重新读。
> - **绝对不能加第三个发射器**。两个已经接近《武士刀零》"一屏 2~4 个敌人"的上限。
> - 高位子弹 y=300 和平台 H/I 顶面 y=414 之间差 114 px —— **站在平台上时子弹从头顶过，完全安全**。这是给玩家的"安全岛"，也是"两条解"的物质基础。
> - E3 放在 (3300, 463) 而不是发射器正下方，是为了让玩家**在砍它的时候还有时间看一眼子弹**。

### 2.7 屏 5 ——「综合考核：弹幕 + 巡逻 + 跨沟」（x 3840–4800）

**把前面所有的东西组合一次，但仍然是"单威胁递进"。**

| 元素 | 坐标 | 参数 | 说明 |
|---|---|---|---|
| **C5 检查点区域** | x 3840–3940 | — | 复活点 **(3860, 465)** |
| **深沟（即死）** | x **4430 – 4590**（宽 160 px），y 480–540 挖空 + 沟底放即死 `Area2D` | — | 160 px > 全高跳的 126 px → **必须用冲刺**（冲刺 87 px + 跳跃 126 px 组合可过） |
| W2 巡逻敌人 | 出生点 (4180, 463) | `patrol_left = -120`、`patrol_right = +120` → **x 4060 ~ 4300**；`can_chase = false` | 在沟的左侧 |
| **S_up 发射器** | (4540, 300) | 周期 **2.4 s**，子弹速 `(-160, 0)`，生成 y=300 | 高位子弹，从沟的上空飞过 |
| **S_dn 发射器** | (4640, 463) | 周期 **1.9 s**，子弹速 `(-160, 0)`，生成 y=463 | 低位子弹，在地面高度飞 |
| E4 静止靶子 | (4760, 463) | 站着不动 | 沟右侧的第一道防线 |
| 平台 J | (4660, 425) | 140 × 22 | 沟右侧的落点安全岛 |

**动线设计（这是全关的高潮）：**

```
       W2 巡逻区               深沟                       落点区
  x 4060 ←─────→ 4300    x 4430┃        ┃4590     ◆J(4660,425)  E4(4760)
                          ┃  ●  ●  ●  ┃  ← 子弹从右往左飞
                          ┃  S_up / S_dn 在沟的右侧
```

**两条解：**

1. **保守（稳）**：先处理巡逻兵 W2（等它转身）→ 站在沟左缘 x=4420 → 观察弹幕窗口 → 冲刺跨沟（87 px 冲 + 空中继续保持水平速度）→ 落在平台 J 或沟右缘 → 斩 E4。
2. **炫技（帅）**：不杀 W2，直接跑到沟边 → 按住 Shift 让世界慢下来 → 用 3.33 倍相对速度从容挑一个窗口 → 冲刺跨沟同时在空中挥刀带走 E4。

**心理曲线：**

1. 「沟！还有子弹！还有那个巡逻的家伙……**这次要素太多了。**」
2. 第一次尝试：处理掉 W2 → 冲到沟边 → 跳 → **掉进沟里**（跳距 126 px < 沟宽 160 px）。
3. 「我跳不过去。……哦，**我有冲刺**。」
4. 第二次：冲刺跨沟 → 一落地被低位子弹打中 → **死**。
5. 第三次：**先开 Shift 看窗口，再冲刺跨沟** → 过。→「**我把三样东西都用上了。**」

**预期重开次数：2~4。预期完成时间：20 秒。**

> 🔧 **摆放要点**：
> - **沟宽 160 px 是精心选的**：它大于全高跳的 126 px（所以必须用冲刺），但小于"冲刺 87 + 跳跃起始水平速度带来的额外位移"（所以不是不可能）。如果你把沟做到 250 px，玩家会怀疑游戏坏了。
> - **绝对不要"必须有子弹时间才能过"**。屏 5 是考核，不是门槛。玩家如果在屏 3、4 都没学会子弹时间，他应该能**靠等窗口 + 冲刺**硬过。逼人用某技能是新手设计者最常犯的错。
> - 沟的即死判定只在 y > 500 的区域生效（`Area2D` + `collision_mask = 2`），别让玩家"贴着沟边走路"就被判死。
> - W2 和沟的水平间距 = 4430 − 4300 = **130 px**。这个距离刚好"跳得过去但很勉强"，让玩家自然地做出"要不要先杀它"的抉择。

## 三、8 条自测验收标准

做完第一关后，**找人试玩**（或者你自己假装第一次玩），逐条验收：

| # | 标准 | 怎么测 | 不通过怎么办 |
|---|---|---|---|
| **1** | **玩家第一次死亡发生在屏 2 之后**（屏 1 不允许出现死亡） | 让 3 个没玩过的人玩，观察他们第一次死在哪一屏 | 屏 1 死了 → 检查平台 A 的高度是否 ≤55 px；检查 E1 是否挡住了玩家的必经之路 |
| **2** | **每次死亡后，玩家能在 3 秒内说出死因** | 死的那一刻直接问他"你刚才为什么死" | 答不出来 → 死因不可归因。检查：威胁是否在屏幕外？是否缺前摇/音效提示？ |
| **3** | **每一屏都存在一条"不死通关"的保守路线** | 自己用"最慢最怂"的打法逐屏通关 | 某一屏必须用子弹时间/必须极限操作 → 改布局，别改数值 |
| **4** | **从死亡到重新可控 ≤ 2.0 秒** | 用 `Time.get_ticks_msec()` 打日志量一下（0.45 s + 复活开销） | 超了 → 检查复活流程里有没有多余的 tween/音效/输入锁定 |
| **5** | **没有任何威胁能从屏幕外攻击到玩家** | 站在每屏最左侧不动，看有没有东西从左边/右边看不见的地方打到人 | 有 → 把发射器/敌人移进屏幕内，或加 1 秒进场预警 |
| **6** | **屏 3 的第一发子弹不会打中玩家**（教学必须零成本） | 从 C3 复活点直接按住"右"不松手，第一个子弹不应命中 | 命中了 → 把 S1 的第一次发射延迟 1.5 秒（`Timer.start(1.5)`）或调整子弹速度 |
| **7** | **一屏里同时威胁玩家的东西 ≤ 2 个** | 逐屏数一遍：同一时刻，玩家视野内需要他"同时处理"的威胁数量 | 有 3 个 → 拆到两个高度、或错开时间、或删掉一个 |
| **8** | **整关速通 ≤ 45 秒**（说明动线没有冗余空跑） | 自己从 C1 一路冲到终点计时 | 超了 → 说明有"空跑段"，把它缩短或改成遭遇；**不要**为了凑时间加敌人 |

**额外的定性验收（做完上面 8 条再问自己）：**

- 屏 3 结束时，玩家有没有发出"哇"的声音？（那是子弹时间的教学成功标志）
- 屏 5 通关时，玩家是觉得"我运气好"还是"我算出来了"？如果是前者，说明窗口设计不够规律——把发射器周期改成更好读的值（比如 2.0 和 3.0，牺牲一点变化换清晰度）。

## 五、新手最常犯的错误（针对"高难度 + 快速重开"）

1. **检查点太远 / 太少。** 最致命。反例："反正重开很快，检查点放关卡开头就行。" **快重开的全部价值在于"复活点贴着难点"**，两者必须配套，否则 0.45 秒的死亡动画只是让你更快地再跑 20 秒空路。
2. **屏幕外的威胁。** 子弹或敌人从屏幕边界外进来 —— 玩家无法归因，只会觉得被坑。要么放进屏幕，要么给 1 秒进场预警（脚步声、屏幕边缘红光、发射器闪白）。
3. **战斗和精密平台跳跃混在同一屏。** 掉坑死 + 被打死混在一起，学习反馈互相污染。**分开做**（本文档把深沟单独放在屏 5，且沟前的巡逻兵和沟后落点都有安全岛，就是为了这个）。
4. **同屏放 2 个以上必须同时处理的威胁。** 一击必杀游戏里，2 个敌人 = 2 倍解法复杂度，3 个 = 8 倍。要么在**空间上分层**（不同高度、不同距离），要么在**时间上错开**（周期不同、一个先动一个后动）。
5. **子弹太快 / 无前摇。** 没有 0.3 秒以上前摇的远程攻击，在子弹时间里也来不及反应，玩家会觉得"这枪兵就是随机致死"。**140~180 px/s 是慢动作游戏里的甜点速度**（对比玩家 220 px/s），再快就变成弹幕游戏了。
6. **用随机性制造难度。** 随机巡逻点、随机弹道、随机发射间隔 —— 这会把"解谜"变成"抽奖"。这也是 Stander 明确拒绝 roguelike 的原因：手工关卡才可控。**所有周期、区间、距离都必须是你手调的常数。**
7. **用无敌帧 / 血量 / 护盾来"救"难度。** 一旦给容错，一击必杀的紧张感就没了，你会被迫不断加敌人数量，最后做成一坨。**正确旋钮是布局和信息，不是数值。**（本项目 `_handle_dash()` 目前没有无敌帧，**请保持这个状态**——加无敌帧会让屏 3~5 的全部设计失效。）
8. **第一屏就上最高强度。** 玩家还没有能力模型。**第一屏的功能是"让玩家成功一次"**，不是筛选玩家。
9. **只做一条解法。** 玩家会觉得自己在"背答案/被摆布"，而不是"解出来了"。每个房间至少给一条保守路线和一条炫技路线。
10. **重开流程里的隐形摩擦。** 死亡音效拖长、屏幕闪白、镜头缓动、UI 淡入、额外的输入锁定 —— 每一项都在偷走"再试一次"的欲望。**你的 0.45 秒要保持纯净。**（`Main.gd` 刻意不 `reload_current_scene()`，这个决定是对的，别改。）
11. **为了让玩家学会某机制而做"教学关"。** 《武士刀零》的做法是把机制放进**能立刻用到的场景**（风扇逼你按 Shift），而不是一段无趣的练习。**你的"教学"应该是屏 3 那颗不打中你的子弹。**
12. **玩家死太多次之后直接改简单。** 如果一屏重开 >5 次，**改布局，不要改数值**：把两个威胁拆到两个高度、删掉一颗子弹、把沟缩窄 20 px。数值调整会掩盖真正的设计问题，还会污染你其他关卡的难度基准。
13. **【本项目特有】设计了一个"没有用武之地"的能力。** 现在的敌人全是静止靶子，**子弹时间对静止靶子毫无收益**——玩家会发现"按住 Shift 除了让自己变慢没有任何好处"，然后彻底不用这个键。这是本文档最想提醒你的一点：**要么给子弹时间配上"与时间有关的威胁"（发射器/移动危险物），要么这个机制就是死的。**
