# 迷刀 Mini（katana-mini）

一个照《武士刀零》核心手感做的跳平台打怪小游戏。**教学项目**，代码全部带中文注释，
参数集中在一处，方便你一边玩一边调。

---

## 现在能干什么

按 **F5**（或命令行跑下面的命令）就能玩：

| 按键 | 动作 |
|---|---|
| **← →** 或 **A D** | 左右移动 |
| **空格** | 跳跃（可长按跳更高，早松手跳得矮） |
| **K** | 冲刺（短促快速，期间无视重力；冷却 0.32 秒） |
| **J** | 攻击（一击必杀） |
| **Shift（按住）** | **子弹时间**——世界慢到 30%，你保持原速 |
| **R** | 重开整关（敌人复活） |

**已实现的《武士刀零》味道：**
- ✅ **一击必杀**——你砍中敌人，它死；它碰到你，你死
- ✅ **死亡零成本**——死了 0.45 秒后自动回**最近的检查点**，**不读条、不闪屏**
- ✅ **冲刺**——短促、快、期间无视重力（悬浮感的来源）
- ✅ **子弹时间**——按住 Shift，世界慢到 30%，玩家速度完全补偿（相对变快 3 倍）
- ✅ **宽容的跳跃**——土狼时间 + 输入缓冲，手感不"硬"

**关卡与敌人：**
- ✅ **3 屏手工关卡**——含 110px 深沟、悬浮平台、**3 个检查点**（复活点贴着难点）
- ✅ **巡逻敌人**——左右巡逻、**走到崖边会掉头**、进入视野会追击
- ✅ **移动危险物（Hazard）**——匀速来回扫动、**带启动前摇**。
  它存在的意义是让「**子弹时间**」有实际用途——静止靶子对慢动作毫无收益，
  没有它的话 Shift 就是个死键
- ✅ **三层视差背景**——天空 / 远山 / 树丛

**故意没做的**（留着以后加）：
- ❌ 弹反子弹 · ❌ 多关卡 · ❌ 音效 · ❌ 存档
- ❌ 敌人多样性（现在只有「静止靶子」和「巡逻兵」两种）

## 怎么跑

> 本项目用 **Godot 4.x**（开发时用的是 4.7.2）。下面命令里的路径请换成你自己的。

**方式一：用编辑器（推荐，能实时看效果）**

用 Godot 4.x 打开本项目目录（含 `project.godot` 的那一层）→ 按 **F5**。

**方式二：命令行**

```powershell
& '<你的 Godot 可执行文件>' --path .
```

**方式三：跑自动化测试（不开窗口）**

```powershell
$godot = '<你的 Godot 可执行文件（建议用 console 版，才有输出）>'

& $godot --headless --path . --script tests/test_core.gd         # CORE_OK       核心机制 11 项
& $godot --headless --path . --script tests/test_slowmo.gd       # SLOW_OK       子弹时间 12 项
& $godot --headless --path . --script tests/test_patrol.gd       # PATROL_OK     巡逻敌人 41 项
& $godot --headless --path . --script tests/test_reachability.gd # REACH_OK      平台可达 9 项
& $godot --headless --path . --script tests/test_sprite.gd       # SPRITE_OK     精灵接入 11 项
& $godot --headless --path . --script tests/test_terrain.gd      # TERRAIN_OK    地形与背景 2 项
& $godot --headless --path . --script tests/test_checkpoint.gd   # CHECKPOINT_OK 检查点与复位 9 项
```

> ⚠️ 两个容易误判的地方：
> - 输出里的 `ERROR: ...` **是正常的** —— SceneTree 脚本里只有 `push_error` 能穿透到终端。
> - **退出码不可靠**，请认 `XXX_OK` 字样判断成败。

**每次改完代码都跑一遍。** 这是你的"安全网"——它保证新功能没把旧功能搞坏。

`test_reachability.gd` 是专门盯"平台跳不跳得上"的。**改平台高度或跳跃参数后必跑它。**

## 手感怎么调（你主要改这里）

全部集中在 **`scripts/Player.gd` 开头的常量区**，改完直接 F5 就能感觉到差别：

| 参数 | 当前值 | 调大会怎样 |
|---|---|---|
| `SPEED` | 220.0 | 跑得更快 |
| `ACCEL_GROUND` | 2400.0 | 起步和转向更"跟手"，但太大会像瞬移 |
| `JUMP_VELOCITY` | -430.0 | 跳得更高（负数向上，别改成正数） |
| `GRAVITY` | 1500.0 | 下落更快、跳跃更"重"，整体节奏变快 |
| `JUMP_CUT_MULT` | 0.45 | 短按跳得更矮；改成 1.0 就没可变跳跃高度了 |
| `COYOTE_TIME` | 0.12 | 离开平台后还能跳的宽限时间，**这是手感的关键** |
| `JUMP_BUFFER` | 0.12 | 落地前提前按跳也生效，**这条让跳跃不"吃键"** |
| `DASH_SPEED` | 620.0 | 冲刺更快 |
| `DASH_TIME` | 0.14 | 冲刺更久 |
| `DASH_COOLDOWN` | 0.32 | 冲刺冷却更长（限制连按） |

### 子弹时间参数（`Player.gd` 同区块）

| 参数 | 当前值 | 说明 |
|---|---|---|
| `SLOW_SCALE` | 0.30 | 世界时间降到多少。**0.1 会拖沓，0.5 又不够爽，0.3 是甜点** |
| `SLOW_LERP` | 8.0 | 进出慢动作的快慢，越大越干脆 |
| `SLOW_ENERGY_MAX` | 1.6 | 能量条满值（秒） |
| `SLOW_DRAIN` | 1.0 | 每秒消耗 |
| `SLOW_REGEN` | 0.55 | 每秒恢复。**比消耗慢，所以不能一直开——这是张力来源** |
| `SLOW_PLAYER_SPEED_KEEP` | 0.0 | **这是子弹时间最关键的旋钮**：<br>`0.0` = 玩家完全保持原速（相对敌人快 3.3 倍）<br>`1.0` = 玩家也跟着变慢（只是"卡顿感"）<br>建议试试 `0.5` 折中一下，感受区别 |

**建议的调法**：一次只改一个，改完玩 30 秒。**手感是试出来的，不是算出来的。**

## 代码结构

```
katana-mini/
├── project.godot          项目配置（输入映射、窗口、物理层都在这里）
├── main.tscn              关卡：地面、平台、敌人、玩家、HUD
├── art/                   ★ 像素图（由 tools/gen_sprites.gd 生成）
│   ├── player_sheet.png   玩家 5列x2行，每帧16x16，共10帧
│   └── enemy_sheet.png    敌人 2列x1行，每帧16x16，共2帧
├── tools/
│   └── gen_sprites.gd     ★ 像素图生成器（改「文字画」就能改素材）
├── scripts/
│   ├── Player.gd          玩家控制器 + 精灵切帧 ← 手感全在这里
│   ├── Enemy.gd           静止敌人
│   ├── PatrolEnemy.gd     巡逻敌人（子代理产出，468 行中文注释）
│   └── Main.gd            关卡逻辑：死亡重开、计分、HUD
└── tests/                 5 套自动化测试
    ├── test_core.gd          核心机制（跳跃/攻击/一击必杀/攻击框）
    ├── test_slowmo.gd        子弹时间（12 项）
    ├── test_patrol.gd        巡逻敌人（41 项）
    ├── test_reachability.gd  平台可达性（6 项）
    └── test_sprite.gd        精灵接入（9 项）← 换素材后必跑
```

**物理层约定**（改碰撞时别搞错）：
| 层 | 用途 | 谁在用 |
|---|---|---|
| 1 | 世界（地面、平台） | 玩家 `collision_mask = 1` |
| 2 | 玩家 | 敌人的 Danger 区 `collision_mask = 2` |
| 3 | 敌人 | 玩家的 AttackArea `collision_mask = 4` |

⚠️ **层号 ≠ 位值**：第 3 层的位值是 `1<<2 = 4`，场景文件里写的是**位值**。
而且 `CharacterBody2D` **默认就在第 1 层**，如果只写 `set_collision_layer_value(3, true)`
会得到 `1|4 = 5` —— 敌人同时属于世界层，**玩家会撞上一堵看不见的墙**。
代码里推荐用 `set_collision_layer_value(层号, true)`（它按层号工作，从 1 开始数）。

## 美术素材：现在用的是什么、怎么换

### 现状：Kenney「Pixel Platformer」（CC0 免费、可商用、无需署名）

- **素材包**：`Kenney Pixel Platformer`（252 个文件，含 License.txt）
- **用到的图块**：角色 `tile_0009`（主角，米色头盔小人）、`tile_0015` / `tile_0016`（敌人）
- **地形**：从 `Tilemap\tilemap.png` 切出 18×18 图块，平铺成三张纹理
- **项目内放置**：`art/kenney/`（原始图块 + 授权文件）

### 关键点：素材是**单帧**的，动画靠"像素位移"生成

Kenney 这套角色**没有动画帧**（27 个角色全是独立的静态图）。所以动作是这样造出来的：

| 状态 | 做法 |
|---|---|
| 待机 | 原图 + 上浮 1px 交替 = 呼吸感 |
| 跑动 | 左倾/右倾/上浮交替 = 前倾后蹬 |
| 跳跃 / 下落 | 整体上移 2px / 原图 |
| 攻击 | 蓄力（上移）+ 前冲 2px = 挥砍感 |

**这不是妥协，是像素游戏常见做法**——但确实比不上真正的逐帧动画。

### 想换素材？改这几处

1. 替换 `art/player_sheet.png` / `enemy_sheet.png`（精灵图）
2. 同步 `Player.gd` 的 `SHEET_COLS` / `SPRITE_SIZE` 常量
3. 同步 `main.tscn` 里 `Visual` 节点的 `region_rect`
4. **跑 `tests/test_sprite.gd` + `tests/test_terrain.gd`**

⚠️ **改完 PNG 必须让 Godot 重新导入**，否则场景会引用到空纹理（不报错，只是白块）：
```powershell
& '<Godot console 可执行文件>' --headless --path '<项目目录>' --import
```

### 另一条路：代码生成像素图（保留着）

`tools/gen_sprites.gd` 能用 **16×16 的「文字画」**生成像素图，一个字符 = 一个像素：

```
.  透明      K  轮廓/头发    S  皮肤     C  外套
W  白/围裙   B  靴子/腰带    G  武器     E  眼睛
```

**想让角色换个样子？直接改那些字符**，然后跑生成器。这条路的产物不如 Kenney 专业，
但**完全归你控制**——想加个披风、改个发色，改字符就行。

### 还想更好看的话

| 方案 | 质量 | 成本 |
|---|---|---|
| Kenney 其他包（有逐帧动画的是 `new-platformer`，但是卡通矢量风） | ⭐⭐⭐⭐ | 免费 |
| AI 生成（PixelLab 等） | ⭐⭐⭐⭐ | $12/月起 |
| 自己画（Aseprite $19.99 / LibreSprite 免费） | ⭐⭐⭐⭐⭐ | 时间 |

⚠️ **AI 生成的授权红线**：Scenario / Leonardo 的**免费档禁止商用**；Steam 上架需**披露 AI 素材**。
Kenney 是 CC0，**没有这些顾虑**。

## 六个踩过的坑（写下来免得重踩）

### 坑 1：Godot 的组不会传递给子节点

`add_to_group("enemy")` 加在 `Enemy1`（父节点）上，但碰撞检测 `body_entered` 返回的是
**碰撞体本身**（子节点 `Body`）——`Body` 不在那个组里，所以 `body.is_in_group("enemy")`
永远是 `false`，`kill()` 从来没被调用过。

**现象**：攻击框明明检测到了敌人（`get_overlapping_bodies()` 返回 1 个），但敌人不死。
**解法**：沿父节点链向上找组（见 `Player.gd` 的 `_find_group_ancestor`）。

### 坑 2：注入输入后必须等 2 个物理帧

在测试里用 `Input.action_press()` 模拟按键，**第 1 帧只记录按键状态，
第 2 帧 `is_action_just_pressed()` 才为 true**。
只等 1 帧就断言，会得到"按键没生效"的假结论。

### 坑 3：`Engine.time_scale` 是全局的，而且会改变"游戏时间"的流速

两个连带效应，都踩过：

- **HUD 和动画会一起变慢**。如果以后加了 UI 动画，记得给对应节点设
  `process_mode = PROCESS_MODE_ALWAYS`，否则菜单在慢动作里也会变慢。
- **物理帧数和游戏时间不再一一对应**。`time_scale = 0.3` 时，
  一个物理帧只推进 `0.3 × (1/60)` 游戏秒。写测试时若按"等 N 秒"折算帧数，
  很容易算错并误判功能失败。**推荐直接用 `_advance_frames(n)` 按帧推进。**
- 另一个隐蔽点：`Engine.time_scale` 在 headless 测试里**会残留**——
  测试异常退出会让后续进程也跑在慢动作下。所以测试结尾务必恢复为 `1.0`。

### 坑 4（最贵的一个）：测试辅助函数会让"成功"看起来像"失败"

我为了验证"平台能不能跳上去"，绕了**十几轮**排查，最后发现**平台参数一直是好的**，
是我的测试辅助函数有 bug：

```gdscript
# 错的写法：落地后又固定等 120 帧，期间一直按着方向键
Input.action_release("jump")
await _adv(100)          # ← 玩家已经落上平台了
await _adv(20)           # ← 但还在往右走，走到平台右边缘掉下去了
Input.action_release(dir)
```

**玩家的行动轨迹是：跳上平台 → 继续向右走 → 从右边缘掉下去 → 落在平台外的地面。**
于是断言"落点在平台上？"得到 `false`，看起来像"跳不上去"。

**正确写法**：一检测到落地就**立刻松开方向键**：

```gdscript
for i in range(150):
    await physics_frame
    if i > 3 and player.is_on_floor():
        break
Input.action_release(dir)     # ← 落地即松手
```

**另外两个同源的坑**（都在同一个辅助函数里，一共三个）：
- **跳跃键必须按住约 18 帧**。`Player.gd` 有可变跳跃高度（松手 `velocity.y *= 0.45`），
  按 1~2 帧就松 → 跳跃被砍半 → 误判"跳不上去"。
- **起跳点有"成功窗口"**。实测平台 A（左边缘 310、顶面 429）：
  起跳 190 → 落点 301（差 9px 撞侧壁）❌；起跳 220/250/280 → ✅。
  **太近撞侧壁，太远飞过平台。** 窗口约在离平台左边缘 30~90px。

**教训**：写游戏测试时，**辅助函数本身就是被测系统的一部分**。
先怀疑自己的测试，再怀疑游戏代码——但**两边都要用数据验证，不能猜**。
